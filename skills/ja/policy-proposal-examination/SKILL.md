# 課題起点の政策案検討

## 目的

「手段ありき」（例: 特定制度の是非）ではなく、**課題を先に固定**し、その課題を説明する変数を洗い、国・都道府県・自治体・独立研究機関などの**公開情報**で裏取りし、取得物をローカルに残してから政策オプションを比較する。

学術向けスキル集における情報源階層（Tier）と、主張（Claim）と根拠（Evidence）の対応の考え方を、政策検討向けに簡略化して使う。

## いつ使うか

- 新しい政策テーマ・課題の検討を始めるとき
- 課題にまつわる変数・データの洗い出しが必要なとき
- 政策案の比較・推敲で、根拠の出所を担保したいとき

## リポジトリ役割

- **本スキル集**: 手順と雛形のみ（公開してよい）
- **具体案リポ**（利用者が別途用意）: `challenges/<slug>/` 以下に課題・出典・政策案を置く（非公開でも可）

スキル本体に具体の政策案や取得データをコミットしない。

## 不変条件

1. **課題先行**: 手段名で議論を始めない。課題文が無いときは先に課題を一文で固定する。
2. **公開情報優先**: 根拠は Tier 1 / Tier 2 のみ。SNS・個人ブログ・まとめサイト・百科事典の直接引用は不可（手掛かりにする場合は必ず一次へ辿る）。
3. **ローカル実体化**: 主張に使う数値・図表・報告書は、URL だけに頼らず具体案リポのローカルに保存し、取得メタデータを残す。保存前の断定はしない。
4. **野良数値禁止**: 出典・取得日・原表の位置が無い数値は本文・比較表に書かない。
5. **モーダリティ**: 根拠の強さに合わせて断定の強さを落とす。欠測は欠測と書く。

## 情報源階層（政策向け）

### Tier 1（最優先）

- 国の統計・白書・法令・審議会資料（例: e-Stat、各省公式、官報）
- 国際公的機関の統計・報告書（OECD、World Bank、UN 系など）
- 査読付き学術論文・公的リポジトリ上の確定データ

### Tier 2（可）

- 都道府県・市区町村の公式統計・交通計画・議会資料
- 公的・準公的な独立研究機関・シンクタンクの報告書
- 大学公式ドメインの紀要・ディスカッションペーパー

### Tier 3（根拠に使わない）

- SNS / 個人ブログ / まとめ / Wikipedia 本文 / 商業 PR
- 手掛かりにする場合は、そこから Tier 1/2 の一次へ辿り、一次だけを保存・引用する

## 作業ディレクトリ（具体案リポ側）

新規課題は本リポの `examples/challenge-template/` を具体案リポへコピーして始める。

```text
challenges/<challenge-slug>/
  challenge.md
  variables.md
  sources/
  sources-index.md
  findings.md
  options.md
  claim-evidence.md
```

`<challenge-slug>` は短い英小文字ハイフン（例: `regional-transit-gap`）。

## 手順

### 1. 課題を固定する（`challenge.md`）

- **課題一文**: 誰の、どの地域・時点の、何が不足／過剰／歪んでいるか
- **望ましくない現状**: 観察可能な現象
- **利害関係者**
- **対象外**
- **検討候補の手段**（任意）: 課題の下位に置く

### 2. 変数インベントリを作る（`variables.md`）

| 列 | 内容 |
|---|---|
| ID | `V01` 形式 |
| 変数名 | |
| なぜ必要か | 課題との論理 |
| 望ましい粒度 | 地域・時間・手段 |
| 想定ソース種別 | 国統計 / 自治体 / 研究 等 |
| 状態 | `needed` / `sourced` / `gap` |

手段から逆算せず、課題の説明・計測・介入評価に必要な変数に限る。おおむね 8〜15 を目安に削る。

### 3. 公開データを取る（Tier 判定 → 取得 → 保存）

1. Tier 1 → Tier 2 の順で探す
2. Tier を判定する。Tier 3 は根拠に使わない
3. `sources/` に保存する（PDF・CSV 優先）
4. `sources-index.md` に追記する

```markdown
### SRC-001
- 標題:
- 発行主体:
- Tier: 1 | 2
- URL:
- 取得日: YYYY-MM-DD
- ローカルパス: sources/...
- 対象変数: V01
- 対象期間・地域:
- メモ:
```

可能なら sha256 も残す。欠測は `gap` とし、推測で埋めない。

### 4. 事実メモ（`findings.md`）

ソースから読み取った事実だけを変数ごとに書く。解釈は Step 5 へ。

### 5. 政策オプション比較（`options.md`）

各オプションに: 介入内容、効く変数、依拠する事実、前提・gap、副作用、実装主体、検証方法。二択に潰さない。

### 6. 主張と根拠（`claim-evidence.md`）

| Claim | Evidence (SRC / 数値) | 対応 | 断定の強さ |
|---|---|---|---|
|  |  | direct / indirect / gap | 断定 / 推定 / 仮説 |

### 7. 返す形

1. 課題一文
2. 充足変数 / gap
3. 有力オプションと支える SRC
4. 次に取るデータ（優先度付き）

## やらないこと

- 課題未定義のまま特定手段の賛否から入る
- Tier 3 を根拠に使う
- ローカル未保存の数値で断定する
- スキル集リポに具体案・実データをコミットする

## 完了条件

- 課題一文がある
- 各変数が `sourced` または `gap`
- 根拠ソースが `sources/` と `sources-index.md` にある
- オプションが事実と gap に紐づく
- 断定には direct な根拠がある
