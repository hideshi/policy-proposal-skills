# 政策オプション比較

## 目的

介入案を複数並べ、事実・欠測・副作用・実装・検証で比較する。**既定では順位付けしない。**

## 利害の原則

1. 受益側（例: 利用者・来訪者）の改善だけを「勝ち」にしない
2. 労働者・住民・事業者などへの分配・負荷・安全を、各 OPT の「副作用・分配」と検証方法に明示する
3. 一方的損失を根拠なしに前提にしない。リスクは仮説として書き、測る指標を置く
4. トレードオフが見えたら緩和・補償・縮小・中止を設計候補に残す
5. 完全な同時 Win-Win は稀。現実目標は悪化させない／測って抑えること

スキーマ正本: [`docs/artifact-contracts.md`](../../../docs/artifact-contracts.md)

## 発動タイミング

- `findings.md` があり、必須変数が `verified` / `partial` / `gap` のとき
- Phase 5

## 手順

1. 必ず `OPT-現状維持` を置く
2. 代替案を `OPT-A`… として契約項目を埋める（費用、権限、可逆性など含む）
3. 各案で「誰が得しうるか／損しうるか」を副作用・分配に書く。損側の指標が無ければ `gap` と検証方法に残す
4. 依拠する事実は `F-ID` を優先
5. 「有力」「推奨」等の順位語を使う場合のみ、ファイル先頭の評価設定（決定主体・成功指標・制約・評価軸・判断理由）を必須記入する。評価軸に分配・安全を含めるかを明示する
6. 評価設定が空のまま順位語を使ったら FAIL。受益側だけの成功定義で順位付けしたら FAIL

## フェーズ判定

| | |
|---|---|
| 必須入力 | findings、必須変数の状態 |
| 出力 | `options.md`（現状維持 + 1つ以上の代替） |
| PASS | 契約項目が埋まり、gap が隠されていない。順位付けなし、または評価設定あり |
| WARN | 費用・権限などが `gap` だらけだが明示されている |
| FAIL | 現状維持案の欠落、findings に無い事実を前提、評価設定なしの順位付け、副作用・分配の欠落、受益側だけの成功定義での順位付け |
| 差し戻し先 | Phase 4 または評価設定の確認 |
| 完了条件 | FAIL でない |
