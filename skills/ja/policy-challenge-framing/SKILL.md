# 政策課題のフレーミング

## 目的

政策手段の名称から議論を始めず、**誰の・どの地域の・何が不足／過剰／歪んでいるか**を一文で固定する。

## 発動タイミング

- 新しい政策テーマを始めるとき
- 課題文が未定、または手段名が課題文の主語になっているとき
- [`policy-proposal-examination`](../policy-proposal-examination/SKILL.md) の Phase 1

## 事前条件

- 書き込み先は**具体案リポ**の `challenges/<slug>/`。スキル集リポ自身やその配下なら停止する
- 具体案リポのルートを利用者に確認してから作成する

## 手順

1. 手段名・関心は「検討候補」に退避し、先に課題を聞く
2. 課題一文・望ましくない現状・利害関係者・対象外・検討候補を対話で埋める（推測で確定しない）
3. 利用者承認後に `challenge.md` を書く
4. 課題文が手段の是非なら書き直しを求める

## フェーズ判定

| | |
|---|---|
| 必須入力 | 利用者の関心または課題候補 |
| 出力 | `challenge.md`（課題一文あり） |
| PASS | 課題一文が手段是非ではなく、承認済み |
| WARN | 対象地域・時点が粗いが一文はある |
| FAIL | 未承認、または手段是非が主語 |
| 差し戻し先 | 利用者との再フレーミング |
| 完了条件 | PASS または WARN |

## 成果物

- `challenges/<slug>/challenge.md`

## やらないこと

- 課題未承認のまま変数洗い・データ収集に進む
- スキル集リポへ具体案を書く
