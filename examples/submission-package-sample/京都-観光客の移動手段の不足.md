## 提出用の一文

車を持たない来訪者が、京都市内および周辺の観光地（時間帯・季節を含む）において、既存の公共交通・タクシー等では移動需要を十分に充足できず、移動の待ち・迂回・機会損失が生じている。

## 課題と対象

# 課題

- **課題一文**: 車を持たない来訪者が、京都市内および周辺の観光地（時間帯・季節を含む）において、既存の公共交通・タクシー等では移動需要を十分に充足できず、移動の待ち・迂回・機会損失が生じている。
- **望ましくない現状**: 観光ピーク時のバス混雑・便数不足、タクシーの待ち・稼働不足、代替マイクロモビリティのカバレッジ不足などが京都で観察されうる。他地域（沖縄・河口湖等）は一般化・比較のための参照候補であり、本課題の第一対象ではない。
- **利害関係者**: 来訪者（特に車非保有）、京都市民・近隣住民、**現地で働く労働者**（タクシー・バス運転者、観光・宿泊・飲食等）、バス・タクシー・マイクロモビリティ事業者、京都市・京都府・観光協会、道路・渋滞の影響を受ける主体
- **インパクトの観点**: 来訪者の移動改善に加え、介入が現地労働者の所得・労働時間・雇用・安全に与える影響（正負）も比較対象に含める
- **対象外**: ライドシェア制度そのものの是非を目的化した議論。全国一律の規制論のみ。貨物物流。京都以外を本丸にした介入設計（比較用データ取得は可）
- **検討候補の手段**（任意・課題の下位）: ライドシェア、バス増便・ダイヤ改善、タクシー供給対策、LUUP等の電動マイクロモビリティ、その他京都固有の手段。手段ありきではなく課題充足で比較する
- **地理スコープ**: 第一対象は京都（京都市および主要な観光移動エリア）。他地域は対照・外挿用
- **具体案リポ確認**: 本ファイルは `policy-proposals`（具体案リポ）側に置かれている
- **きっかけメモ**: 利用者投稿は課題フレーミングの手掛かり（Tier3、根拠に使わない）

## 課題分析

# 課題分析メモ（京都・観光客の移動手段の不足）

更新: 2026-09-14（Sol レビュー反映）  
位置づけ: **政策の採択案ではない。** 公開情報で押さえた現状の整理と、次に何を測るべきかの土台。  
正本の数字・出典は `findings.md` / `sources-index.md` / `institution-memo.md`。主張の監査は `claim-evidence.md`（本メモも監査対象に含める）。  
実証の起票は `pilot-tickets.md`。

## 0. 利害の原則（根幹）

完全な同時 Win-Win は稀である。それでも案づくりの根幹は次とする。

1. **受益側だけを勝ちにしない。** 来訪者の移動改善と、労働者・住民・事業者などへの影響を同じ表で見る。
2. **一方的に負ける前提を、根拠なしに推し進めない。** 分配悪化を事実として断定しない一方、リスク仮説は隠さない。
3. **トレードオフは測る。** 悪化しうる指標（所得、労働負荷、事故、苦情など）を検証設計に入れる。
4. **緩和・補償を設計候補にする。** 悪化が見えたら縮小・中止・補償を選択肢に残す（安全中止基準を含む）。

現実的な目標は「全員が同時に得をする」より、**片方を良くしつつ、もう片方を悪化させない／悪化を測って抑える**ことである。

## 1. 課題

車を持たない来訪者が、京都市内および周辺の観光地（時間帯・季節を含む）で、既存の公共交通・タクシー等だけでは移動需要を十分に満たせず、待ち・迂回・機会損失が起きうる。

待ち時間（分）の直接統計はまだ無い。いま言えるのは、タクシーのマッチング不足（定義付き）、観光客の残念理由、市民の混雑認識などからの**示唆**まで（CLM-013 WARN）。

### 1.1 測定上の対象定義（暫定）

地理・統計の単位が資料ごとに違うので、同一視しない。

| 軸 | 暫定の定義 | 注意 |
|---|---|---|
| 地域（課題の主戦場） | 京都市内の主要観光移動エリア（寺社・駅前・幹線バス停周辺など） | 「周辺」は観光地アクセスに限る |
| 地域（タクシー不足指定） | **京都市域交通圏**（市外の一部市町を含む。F-039 等） | 京都市 ≠ 京都市域交通圏 |
| 地域（市バス） | 京都市交通局の市バス事業 | 交通圏全体のタクシー制度とは母集団が違う |
| 来訪者属性 | 課題文は「車を持たない来訪者」。既存 F-006/007 は主に**日本人来訪者の手段構成** | 車非保有の直接識別は未充足（V07 は手段構成まで） |
| 時間帯 | 観光ピーク（日中〜夕方）と、制度上の深夜不足帯は分けて扱う | 後者を前者の代理にしない |
| 移動局面 | 市内二次交通・観光地間・帰宅／宿泊地への個別輸送 | 入洛の長距離鉄道は課題の主対象外 |

## 2. 現状で押さえる事実

### 需要側
- 令和7年の観光客数は **6,279万人**（F-001）。月別繁閑は約 **1.3倍**（F-004/005）。
- 日本人の入洛は鉄道中心。市内ではバス利用が厚い一方、タクシーも一定の選択肢（F-006/007）。これは手段構成の記述であり、「車非保有者」そのものの規模ではない。

### 供給側（既存）
- 市バスは輸送規模が大きい（F-014/015）。運転士不足（非常事態宣言、必要880に対し実稼働830）は供給制約の候補（F-013, F-033/034）。
- **営業係数・赤字／黒字系統数（F-016）は財務上の実装制約の候補**であり、混雑や観光移動不足の直接証拠ではない。系統選定では乗車不能・積み残し・遅延などを別途使う。
- 京都市域のタクシー登録は **5,574台**（F-008）。制度創設時公表では、金土日16時–翌5時などで不足が最大 **約490台**（マッチング率90%定義、F-009/F-038。公表時点は創設時資料）。

### 労働
- 府のタクシー運転者は平均年齢 **66.6歳**、月々の給与（残業込み）約29.8万円（F-011）。自動車運転従事者の有効求人倍率は京都で **3.67**（F-032）。高齢化と求人逼迫は、供給を増やす話の**文脈・制約候補**（因果の順位付けはしない）。

### 制度（C/D）
- **日本版ライドシェア（自家用車活用）**は、法人タクシー事業者の許可・管理下の枠（道路運送法78条3号）。単独型の一般ドライバー有償は本制度の説明範囲外（F-035/036, CLM-034/040）。対応変数は V04（補助）および制度適合 V13。
- 京都市域の**現行**不足指定（公表日 **令和8年2月26日**）は、月〜金 **1〜4時台 10台**、日 **0〜5時台 50台**。夕方〜夜の通常枠は無い（F-039, CLM-035）。許可事業者は一覧上 **16者**（表時点 R8.7.23, F-042）。
- **特定小型原付**は、基準適合なら16歳以上・免許なしで原則車道。歩道は特例＋標識のみ。市は自賠責・ナンバー・税年2,000円を整理（F-044/047）。対応変数は V06（補助）および制度適合 V14。

| 測り方 | 母集団 | 地理単位 | 観測期間の例 | データ範囲 | V-ID | いま分かること | これだけでは言えないこと |

# 実証実験の起票（素案）

更新: 2026-09-14（Sol レビュー反映）  
位置づけ: 実装指示書ではない。**何を・どの範囲で・何と比べて測るか**の起票ドラフト。  
詳細の制度条件は `institution-memo.md`。課題との接続は `analysis.md`。

## 共通ルール

**利害の原則:** 来訪者指標の改善だけを成功にしない。労働・住民・事業者側の悪化リスクを副次または主監視に入れ、閾値超で縮小・中止できる設計にする（`analysis.md` §0）。

- 効果・分配は測るまで断定しない
- 制度枠外（単独型有償、基準外キックボードの免許なし運転など）は対象にしない
- **制度指標**（マッチング率・不足車両数）と **課題指標**（待ち分・乗車不能・目的地到達など V08 系）を併記する。前者の改善だけを課題解決と呼ばない
- 来訪者／住民／運転者を識別できる記録項目を先に決める
- 結果は `findings.md` に事実として戻し、効果断定は `claim-evidence.md` を通す（本起票も監査対象）

| 範囲 | 観光ホットスポット周辺の限定エリア。**原則車道。歩道は特例標識区間のみ**（C-tokutei） |
| 介入（効果検証・アームごと） | ポート配置・案内・安全周知など、アームごとに固定したパッケージ |
| 主指標 | **旅行完了率**（意図した OD を完了できた割合）または **移動時間（分）** のどちらか一つ |
| 副次 | 貸出回数、平均距離・時間、代替元交通手段、利用できなかった理由、ポート回転率 |
| 安全指標 | 対人事故・歩行者苦情・放置違反を **千回利用あたり**（または千kmあたり）で定義 |
| 制度指標との関係 | バス混雑・タクシーマッチングは副次参考。主成功条件にしない |
| 対照 | 導入前期間、または未導入の類似エリア（選定理由を文書化） |
| 交絡 | 天候、坂、荷物、イベント、既存シェアの自然増 |
| 実施前ゲート | 公有地占用、個別協定、追加走行禁止の有無、基準適合車のみ貸出、年齢確認 |
| 個人情報 | 事業者ログの OD・端末 ID の扱い |
| 安全中止 | 千回あたり事故／重大苦情が事前閾値を超えたら当該アーム停止 |
| 対応 ID | V06, V08, V14 / OPT-C / CLM-037,038 ほか |
| 成功の見方 | 測定可能性: 主指標と安全レートが取れる。効果検証: アーム別に課題指標が比較できる。幹線代替の可否はデータが出るまで書かない |

## TICKET-D — 自家用車活用：現行枠の運用実態観測（効果検証は分離）

| 欄 | 内容 |
|---|---|
| 状態 | `DRAFT`（個別配分台数未確認 → `DATA-BLOCKED` / `LEGAL-BLOCKED` の可能性） |
| チケット種別 | **`運用実態観測`（本チケット）**。運用改善の効果検証は **TICKET-D1** に分離。臨時措置は **TICKET-D2** |
| 目的 | 現行通常枠で、何台・何時間が動き、誰が乗っているかを記述する。**観光課題の解決を目的にしない**（来訪者比率が小さい場合は特に） |
| 範囲（必須） | 月〜金 **1〜4時台**（不足指定10台）、日 **0〜5時台**（50台）（F-039, 公表 R8.2.26）。許可タクシー事業者の管理下のみ |
| 介入 | **なし**（観測のみ）。「運用改善」は D1 |
| 主指標 | **実働車両時間**（台×時間） |
| 副次・算式に注意 | (1) 需給: マッチング率・不足車両数（F-039 定義）は**需給指標**として別掲。(2) **消化率の分母に F-039 の不足台数を使わない**。消化率を出すなら `実働車両時間 / 各社に通知された使用可能車両時間`（個別通知の取得がゲート） |
| 課題指標 | 待ち分・失敗率は取れる範囲で併記。あわせて **利用者区分（来訪者／住民／不明）** を可能な方法で識別。来訪者比率が低い場合、観光課題への効果検証は目的から外す |
| 分配・安全 | 同帯の法人タクシー実車・所得（取れる範囲）、事故・クレーム |
| 対照 | 観測フェーズでは「対照による効果推定」を主目的にしない。記述の比較用に隣接帯を見る場合は、制度条件・需要構成の差を明記 |
| 実施前ゲート | 個別配分台数・経過措置の確認、運輸局・事業者の協力、データ項目の合意 |
| 個人情報・営業情報 | 事業者別実働の集計公表基準 |
| 対応 ID | V04, V08, V09, V13 / OPT-D / CLM-035,036,039 |
| 成功の見方 | 実働・利用者区分・需給指標が時点付きで残る。課題解決の断定はしない |

### TICKET-D1 — （将来）運用改善の効果検証

- 種別: `効果検証`
- 前提: D の観測でベースラインとデータ取得が通っていること
- 介入: **一つに固定**した運用変更（例: 特定帯のシフト誘導）。内容が決まるまで起票を `DRAFT` のままにする

- 消化率を使う場合も分母は通知済み使用可能車両時間
